The newer example and dated Maven directories supply the pins above. These pages are not synchronized; do not silently treat one as the only current answer. All read 2026-10-26.

Web browsing can read upstream HTML and raw template files, but Fabric Meta's Loader endpoint, Mojang's version manifest, and XML Maven metadata could not be read through the web tool. The [Meta endpoint](https://meta.fabricmc.net/v2/versions/loader/26.3) is a future cross-check, **not successful evidence here**. ## Player installation on Windows, macOS and Linux

Use the official Minecraft Launcher with Java Edition ownership. Launch vanilla **26.3** once to download its game/runtime, reach the menu, then close both the game and launcher. Keep the profile's Java executable on the launcher's bundled/default runtime. The game needs **Java 25**; the launcher supplies it. A universal Fabric installer `.jar` may additionally need system Java because launching a file from the desktop/terminal does not automatically use that bundled runtime. Sources: [Mojang runtime](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-1), [Fabric Windows guide](https://docs.fabricmc.net/players/installing-fabric/windows), [macOS guide](https://docs.fabricmc.net/players/installing-fabric/macos), [Linux guide](https://docs.fabricmc.net/players/installing-fabric/linux), all read 2026-10-26.

1. Download [Fabric installer 1.1.2](https://fabricmc.net/use/installer/). On Windows use `.exe` (uses the launcher's Java). On macOS/Linux use the universal `.jar`; install [Temurin Java 25](https://adoptium.net/temurin/releases/?version=25) if no system Java is available. On Linux/macOS a terminal can run `java -jar fabric-installer-1.1.2.jar` from its download directory. See the OS-specific Fabric guides linked above (read 2026-10-26).
2. In **Client**, select Minecraft **26.3** (or a 26.3.x hotfix), Loader **0.20.1 or newer** (the installer's latest selection is fine), the launcher's correct game installation location, and **Create Profile**, then **Install**. Reopen the launcher and choose the corresponding Fabric profile; `fabric-loader-0.20.1-26.3` is the baseline example, not a required display name. If missing, enable modded installations under **Installations**. The installer installs Loader; it does not supply every mod. Sources: [official installer](https://fabricmc.net/use/installer/), OS guides above, read 2026-10-26. The accepted runtime ranges are this project's compatibility policy.
3. With Minecraft closed, put **`unallocated-0.1.11.jar`** in the selected profile's `mods` directory. Extract the CI artifact ZIP first; do not extract the mod JAR. Fabric API **0.165.0+26.3** is included as seven nested modules; **do not download or install it separately**. Loader + this one JAR is the installation path. General mod placement source: [Fabric Installing Mods](https://docs.fabricmc.net/players/installing-mods), read 2026-10-26.

| OS | Default `mods` directory | Opening it |
| --- | --- | --- |
| Windows | `%APPDATA%\.minecraft\mods` | Win+R, paste the directory, Enter. |
| macOS | `~/Library/Application Support/minecraft/mods` | Finder → Go → Go to Folder, paste the directory. |
| Linux | `~/.minecraft/mods` | File manager location field; Ctrl+H reveals hidden directories. |

4. Select the Fabric 26.3 profile and **Play**. Choose **Singleplayer** and create a disposable world. This package only logs `UNALLOCATED initialized (common).` and `UNALLOCATED initialized (client).` in `<Game Directory>/logs/latest.log`; there is no scenario/map yet. Successful launch, both log lines and a world opening without a crash are the manual smoke-check criteria.

## Build and handoff

The repository intentionally has no wrapper scripts/JAR. On a development machine with adequate memory, install JDK 25 and Gradle 9.8.2, then run `gradle --no-daemon --console=plain build`. The production JAR is `build/libs/unallocated-0.1.11.jar`; the non-remapping plugin does not require `remapJar`. Do not run this here.

CI installs the selected Gradle distribution, compiles the common/client code and the isolated smoke helper, builds and inspects the player JAR, runs the server/client smoke checks, then uploads the installable JAR plus its SHA-256 checksum. Gradle's action owns the dependency and asset cache; PR runs read it without writing, push runs may write it. No duplicate `setup-java` cache, secrets, publishing credentials, or wrapper binary downloads are required from the coordinator.

### Real dedicated-server smoke check

Every push and PR runs `python3 scripts/smoke_test.py server` after building and verifying the player JAR. It downloads the [official Fabric server launcher](https://fabricmc.net/use/server/) through its fixed-version [Meta URL](https://meta.fabricmc.net/v2/versions/loader/26.3/0.20.1/1.1.2/server/jar): Minecraft 26.3, Loader 0.20.1, installer 1.1.2. The launcher supplies the real game and libraries. Source read 2026-10-26; unlike the earlier build, this new smoke check still awaits its first CI result.

The script creates `.tmp/smoke/server`, copies the exact release JAR into `mods/` and verifies its SHA-256, accepts the EULA only in that disposable CI directory, and starts a 1 GiB headless Java 25 server on loopback with a flat world and minimal view distance. No separate Fabric API or test helper mod is installed on the clean server. The six common API modules come from the player JAR and their exact versions must appear in Loader's startup log. The seventh module, screens, is client-only; [Loader 0.20.1 resolution](https://raw.githubusercontent.com/FabricMC/fabric-loader/0.20.1/src/main/java/net/fabricmc/loader/impl/discovery/ModResolver.java) ignores schema-1 positive dependencies when the matching bundled module is disabled for the current environment (source read 2026-10-26). A second, isolated `server-with-api` run also installs the full pinned API to exercise Loader's duplicate-module resolution. It requires the **actual `logs/latest.log`** to contain both `UNALLOCATED initialized (common).` and `Done (...)!` within 120 seconds, sends `stop` through stdin, then requires `Stopping server` and exit status zero within 30 seconds. A crash report, fatal JVM/Mixin message, missing evidence, early exit, or deadline fails the job. Each run starts fresh; stale logs cannot pass.

Console logs, game logs, screenshots and crash reports are uploaded as `smoke-diagnostics-<commit SHA>` even on failure. The installable artifact is uploaded only after both smoke checks succeed. The server step has a four-minute hard limit, and the overall workflow sixteen minutes; the small flat world should ordinarily finish much sooner. No game process is run on the scaffold machine.

### Real production-client smoke check

Client game tests exist for 26.3: the upstream branch contains [`FabricClientGameTest`](https://raw.githubusercontent.com/FabricMC/fabric-api/26.3/fabric-client-gametest-api-v1/src/client/java/net/fabricmc/fabric/api/client/gametest/v1/FabricClientGameTest.java) and [`ClientGameTestContext.waitForScreen`](https://raw.githubusercontent.com/FabricMC/fabric-api/26.3/fabric-client-gametest-api-v1/src/client/java/net/fabricmc/fabric/api/client/gametest/v1/context/ClientGameTestContext.java). The [26.3 lifecycle documentation](https://raw.githubusercontent.com/FabricMC/fabric-api/26.3/fabric-client-gametest-api-v1/src/client/java/net/fabricmc/fabric/api/client/gametest/v1/package-info.java) says the game closes after the tests. [Fabric's testing guide](https://docs.fabricmc.net/develop/automatic-testing) documents production client testing under Xvfb; [Loom production tasks](https://docs.fabricmc.net/develop/loom/production-run-tasks) accept explicit mod JARs and a run directory. Sources read 2026-10-26. The general guides currently identify themselves as 26.2; the 26.3 interfaces above were checked separately. This is sufficient upstream support to implement the test; success on our runner still requires the next CI run, with no silent skip/fallback.

`src/clientSmoke` builds a separate helper JAR under `build/smoke`. Its only nested module is `fabric-client-gametest-api-v1:6.0.11+131f8d475d`, resolved without transitive dependencies. None of the seven shipped modules can come from the helper. `runClientSmoke` copies the release artifact into a fresh client `mods/` directory and injects only the helper through Loom's `fabric.addMods`; there is **no standalone Fabric API JAR**. The helper verifies the loaded UNALLOCATED bytes, all seven module origins (`NESTED`, parent `unallocated`), lifecycle/command/network/resource interfaces, an actual `ScreenEvents.AFTER_INIT` callback for the title, then captures the title screen. The watchdog also checks that `mods/` contains only the player artifact. See [Loom 1.19 production launcher source](https://raw.githubusercontent.com/FabricMC/fabric-loom/1.19/src/main/java/net/fabricmc/loom/task/prod/AbstractProductionRunTask.java) (read 2026-10-26) for helper injection.

CI uses Ubuntu 24.04, Xvfb/Xauth and Mesa software graphics, setting `SDL_VIDEODRIVER=x11`, `LIBGL_ALWAYS_SOFTWARE=true` and null OpenAL output. The watchdog reads `.tmp/smoke/client/logs/latest.log`, requiring **both** real mod entrypoint messages and the helper's title-screen marker, a PNG screenshot, and process exit zero within 240 seconds. Crashes, missing logs/screenshots and hangs fail the job. The audio package also opens a single-player world and requires seven STARTED layer markers plus attenuation, expiry and cleanup assertions. It does not cover the full home installation path. No Minecraft account or extra secret is needed for the client game-test harness.

The player JAR gate (`scripts/verify_jar.py`) permits **exactly** the seven nested artifacts in `fabric-api-modules.json`, with exact filenames and the expected mod ID and version read from each nested `fabric.mod.json`. It validates both the physical archives and Loader's `jars` declarations, nested dependency closure, environments, Apache-2.0 metadata and retained licenses. It rejects test entrypoints/classes, unknown or recursively nested archives, duplicate ZIP entries, changed metadata and player artifacts over **2 MiB**. The seven upstream module JARs total 1,728,621 bytes before the outer ZIP compresses them; this is an upstream reference size, not an assertion of byte-identical nested output. This is a subset of the API, with no renderer, datagen or gametest modules shipped to players.

`META-INF/NOTICE-Fabric-API.txt` credits FabricMC and contributors and points to [Fabric's source](https://github.com/FabricMC/fabric/tree/26.3). The complete upstream Apache License 2.0 is reproduced in `META-INF/licenses/Fabric-API-Apache-2.0.txt`; every module retains its original license. UNALLOCATED's own All-Rights-Reserved metadata does not replace those upstream licenses.

To extend this set, inspect the actual pinned module metadata and dependency closure, add only required modules to the lock, update credits, the smoke module-origin expectation and the size budget if needed, then require green CI without external API. `include` is non-transitive ([Loom documentation](https://docs.fabricmc.net/develop/loom/#dependency-configurations), read 2026-10-26); the build uses ordinary `implementation` for 26.3's non-remapping plugin. The lock is based on each published module's `fabric.mod.json` in the reference API 0.165.0+26.3 JAR. Nested ZIP byte identity is not required: CI run 40293376632 (a0def95) failed that assumption at the API base module. Repackaging that preserves approved metadata is accepted; wrong IDs or versions, extra or missing modules and recursive nested jars still fail. SHA-256 remains the checksum of the final player artifact, and smoke checks still verify the installed player JAR against that artifact.

Python tests exercise watchdog failures and adversarial packaging fixtures without invoking Java. The real server (clean and full-API coexistence) and title-screen/audio client run only in CI, retain their strict deadlines, and fail on missing evidence. CI run 40293376632 compiled the package but failed the former nested-byte hash gate before smoke tests; the corrected metadata gate and real-game runs await the next CI result. No local game launch is claimed. A human still needs to install Loader + one JAR on a home machine, reach a world and confirm rendering with OpenGL (CI exercises the software graphics path).
